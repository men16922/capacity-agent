# 계산서 이후에 남겨야 할 구축·검수 증거

자료 09~15는 보안 설계, 구축 계획, 하드웨어·소프트웨어 구성과 완료 보고서로 이어진다. 따라서 향후 에이전트는 용량 수치 외에도 요구사항과 검수 항목을 연결할 수 있다.

| 산출물 | 포함할 내용 | 완료 판단 근거 |
| --- | --- | --- |
| 사양서 | 역할, 수량, 자원, 기능, 지원 조건 | 산정 및 설계 요구와의 대응 |
| 설치 목록 | OS·미들웨어·버전·설정·담당 | 실제 설치 내역과 화면·로그 |
| 구성 점검표 | 설계·구매 사양과 실제 구성 비교 | 일련번호·자원·접속·동작 증적 |
| 보안 점검표 | 물리·펌웨어·계정·서비스·정책 | 적용 결과와 동작 확인 |
| 완료 보고서 | 차이, 미완료, 증거, 유지보수 조건 | 검수자의 확인 |

LLM이 할 수 있는 일은 항목 초안, 누락 탐지, 근거 연결이다. 실제 점검을 하지 않은 항목은 미점검으로 남긴다. 보안표에는 “불필요한 계정이 존재하는가”와 “접근이 제한되는가”처럼 질문 방향이 다르므로 예/아니오를 같은 방식으로 채점하지 않는다.

현재 ISMS·ISMS-P 엑셀의 버전과 현행 인증 기준 일치는 확인되지 않았다. 여기서는 문서의 구조와 점검 업무 흐름을 정리하며 현행 법규·인증 요구에 대한 적합성 판단은 다루지 않는다.

HWP는 본문·미리보기 텍스트를 추출했지만 표 배치와 정확한 셀 관계는 미검증이다. 소프트웨어 설치 XLSX의 화면 시트도 그림이 있을 수 있다. 텍스트가 없는 것을 증거가 없는 것으로 단정하지 않는다.

추가된 [클라우드 취약점 점검 가이드](../sources/pdf-1e5aa3fe692c.md)의 39종 기술별 설정 점검을 [클라우드 보안 검토](cloud-security.md)에 연결했다. 적용 여부·점검 상태·증적을 분리하며 용량산정 완료를 보안 점검 완료로 처리하지 않는다.
