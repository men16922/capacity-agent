# 요구사항을 계산 입력으로 바꾸기

“느리지 않아야 한다”만으로는 용량을 산정할 수 없다. 서비스, 사용자, 업무 빈도, 데이터, 목표 시점과 응답 조건을 확인해야 한다. 강의 01·02와 요구사항 양식은 원문 요구에서 시스템 요구, 자원 영향, 우선순위로 이어지는 흐름을 제공한다.

| 분류 | 확인할 입력 | 확인할 의미 |
| --- | --- | --- |
| 사용자 | 전체·활성·동시 사용자 수 | 각 수의 관측 구간과 정의가 같은가 |
| 업무 | 사용자당 업무 수, 업무당 트랜잭션 수 | 초당·분당을 구분했는가 |
| 응답 | 응답시간 목표와 백분위, 처리량 | 평균만으로 피크를 설명하고 있지 않은가 |
| 데이터 | 현재 크기, 증가량·증가율, 보관 기간 | 원본·인덱스·로그·백업이 중복되지 않는가 |
| 가용성 | 허용 장애, 장애 시 부하, 복구 목표 | 예비 서버가 정상 시 용량에도 포함되는가 |
| 제약 | 목표 연도, 설치 장소, 예산, 사용 기술 | 확정값인가, 가정인가, 미정인가 |

각 값에는 `value`, `unit`, `source`, `basis_date`, `assumption`, `confirmed_by_user`를 붙이는 것을 제안한다. 값이 없으면 `null`과 추가 질문을 남기고 0으로 대체하지 않는다.

질문의 예: “사용자 1만 명은 가입자 수인가, 피크 동시 세션 수인가?”, “분당 요청 2건은 한 사람 기준인가, 시스템 전체 기준인가?”, “백업은 몇 세대이며 같은 스토리지에 보관하는가?”

이 문서의 입력 스키마와 질문 예시는 제품 설계 제안이다. 강의 양식을 그대로 구현한 것은 아니다.
