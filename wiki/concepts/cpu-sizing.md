# CPU 성능 요구와 장비 선정은 두 단계다

TTA R3의 CPU 산정 결과는 코어 수가 아니라 벤치마크 기준의 성능 요구량이다. WEB/WAS는 `max-jOPS`, OLTP는 `tpmC`를 사용한다. 실제 코어 수나 서버 대수로 바꾸려면 동일 벤치마크 유형의 장비 성능 자료와 배치·장애 조건이 추가로 필요하다.

## WEB/WAS

동시 사용자 수와 사용자당 초당 오퍼레이션 수에 기본 OPS, 업무용도, 인터페이스, 피크, 연계, 클러스터 및 시스템 여유 계수를 곱하고 목표 활용률과 단위 보정으로 나눈다. TTA R3 표 7-1, PDF p.19~20이 근거다.

단위 보정은 벤치마크 유형과 서버 계열에 따라 다르다. 표 7-7, PDF p.25~26의 Composite 값은 x86 29·미정 30·Unix 31이며 MultiJVM은 x86 24·미정 25·Unix 26이다. 선택한 값을 결과에 기록한다.

SPEC은 max-jOPS를 처리량 지표로, critical-jOPS를 응답시간 제약을 고려한 처리량 지표로 구분한다. 따라서 max-jOPS 산정만으로 서비스 응답시간 목표를 충족한다고 결론내리지 않는다. SPEC 공개 결과의 실행 범주 간 비교도 허용하지 않으므로 장비 비교에서는 Composite와 MultiJVM을 분리한다. [SPEC 공식 실행·보고 규칙 §3.1](https://www.spec.org/jbb2015/docs/runrules.pdf)

## OLTP

시작 입력은 **시스템 전체의 분당 트랜잭션 수**다. 동시 사용자 방식이라면 사용자 수 × 사용자당 분당 업무 수 × 업무당 트랜잭션 수로 산출한 뒤 각 보정계수를 적용한다. 업무 TPS를 입력받는 경우 분당으로 바꾸는 단위 변환과 tpmC 모델의 보정을 구분한다. 표 7-8 및 §7.1.2, PDF p.26~33이 근거다.

## 구현할 때

[공식 벤치마크 안내](../benchmarks.md)에서 TPC-C 전체·비클러스터 결과와 상세 보고서 링크를 확인한다. `tpmC`는 CPU 단품 점수가 아니라 시험 구성 전체의 처리량이다.

성능 요구량과 장비 구성 추천을 다른 출력으로 둔다. 장비 자료가 없으면 성능 요구량까지 반환한다. 코어당 임의 상수를 만들어 코어 수를 확정하지 않는다. 클러스터 보정과 장애 대비 대수 계산은 중복 적용 여부를 명시한다.
