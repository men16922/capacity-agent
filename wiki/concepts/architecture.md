# 산정 결과를 구성안과 연결하기

같은 총 CPU 성능과 메모리라도 서버 역할 분리, 장애 시 남는 노드, 데이터 경로에 따라 서비스 특성은 달라진다. 요구사항 → 부하 → 산정 → 아키텍처 → 장비 선정 → 검증의 연결을 유지한다.

| 설계 대상 | 기록할 결정 | 산정에 주는 영향 |
| --- | --- | --- |
| 서버 | WEB/WAS/DB 배치, 계층 분리, 가상화 | 역할별 성능 요구와 자원 배분 |
| 스토리지 | 연결 방식, RAID, 데이터·백업 배치 | 사용 가능 공간, 성능, 장애 범위 |
| 네트워크 | 계층별 트래픽, 포트, 이중 경로 | 병목과 장애 시 가용 대역폭 |
| 가용성 | 정상·장애 시 활성 노드, 복구 조건 | 정상 시 합산 용량과 장애 시 용량 |
| 구축 | 순서, 이관, 되돌리기, 검수 | 설계 의도와 실제 증적의 연결 |

TTA R3 표 6-7(PDF p.19)은 계층 결합 방식에 따른 가중치를 제시한다. 예를 들어 WEB/WAS 결합 서버에는 1.6이 제시되어 있다. 이를 적용했다면 결과에 별도로 표시하고, 역할을 나누어 이미 합산한 계산과 중복 적용하지 않는다.

초기 제품은 자원별 요구량과 가정을 먼저 제공한다. 장비 카탈로그를 추가하는 단계에서 모델, 벤치마크 범주, 구성, 측정일, 출처, 가격 기준일, 제공 용량을 비교한다. 과거 HWP의 제품명·가격은 사양서 구조를 이해하는 예시다.
