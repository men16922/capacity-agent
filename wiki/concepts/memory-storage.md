# 메모리, 디스크 공간, IOPS를 따로 산정하기

메모리는 실행 중인 시스템과 사용자·애플리케이션이 요구하는 공간이다. 디스크는 보관할 데이터와 소프트웨어가 차지하는 공간이다. IOPS는 초당 입출력 동작 수이며 저장 용량과 별개다.

| 대상 | TTA R3 본문의 계산 구조 | 추가 확인 |
| --- | --- | --- |
| 메모리 | `(시스템 + 사용자당 메모리 × 동시 사용자 + 앱 메모리) × 버퍼 보정 × 여유 계수` | 시스템·힙·공유 캐시의 중복 여부 |
| 시스템 디스크 | `(OS + 앱 + SWAP) × 파일시스템 보정 × 여유 계수 × RAID 계수` | SWAP은 같은 용량 단위로 더함 |
| 데이터 디스크 | `(데이터 + 백업) × 파일시스템 보정 × 여유 계수 × RAID 계수` | 인덱스·로그·백업 보관 정책 |
| IOPS 추정 | 산정 tpmC × OLTP 0.03 또는 Batch 0.01 | 해당 표준 모델의 경험적 추정 |

메모리는 TTA R3 §7.2, PDF p.33~35이며 in-memory 시스템은 같은 기준의 적용 대상에서 제외한다고 명시한다. 디스크는 §7.3, PDF p.35~37, IOPS는 §7.4, PDF p.38이다.

## 용량을 혼동하지 않는 출력

[SPC-1·SPC-1C 공식 벤치마크 안내](../benchmarks.md)에서 시스템과 구성요소 시험을 구분하고 IOPS·지연·시험 용량·구성을 확인한다.

웹 산출물은 논리 데이터량, 백업량, 보정 후 필요량, RAID를 포함한 물리 용량, 선택 장비의 실제 제공량을 구분하는 것이 좋다. TTA의 RAID 1.3·1.4는 해당 산정 모델의 계수이며 모든 RAID5·6 구성의 정확한 효율은 아니다. 실제 디스크 개수와 스페어가 정해지면 별도의 토폴로지 검증이 필요하다.

MB·GB 표기를 자동으로 MiB·GiB로 간주하지 않는다. 원문 단위와 실제 입력의 십진·이진 정의를 저장하고, 단위가 확정된 다음 변환한다. 포맷 여유, 파일시스템 보정, RAID 보정의 중복도 점검한다.

표준 부록 PDF p.44의 약 5,585MB 산정 후 1,024MB 선정 문구는 원문에 존재하는 불일치다. 산정치보다 작은 구매 용량을 허용하는 근거로 사용할 수 없다. [검토 기록](../open-questions.md)
