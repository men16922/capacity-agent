# On-Prem → AWS 마이그레이션 설계

2026-09-27, 구현 계약. 웹 제품의 핵심 흐름이다. [화면 계획](WEB_PLAN.md)과 [AWS 워크북](../wiki/sources/xlsx-d6bfd84a3ce8.md)의 실측·직접 경로를 근거로, 기존 TTA 계산과 분리한 결정론적 모듈을 만든다.

## 사용자가 얻는 결과

현재 서버를 선택하면 AWS 요구 사양, 조건에 맞는 EC2 후보, gp3 용량·IOPS·처리량, 공식 단가 스냅샷 기준 월 예상 비용과 계산 근거를 얻는다. 자산별 입력·가정을 수정하고 여러 이전안을 저장·비교하며, 산정서를 JSON과 인쇄로 내보낸다. 실제 데이터 이관이나 클라우드 자원 생성은 수행하지 않는다.

## 자산과 계산 단위

자산 한 행은 하나의 기존 서버 또는 VM을 나타낸다. 이름·역할·OS·아키텍처·할당 논리 CPU·메모리 GiB·디스크 사용 GiB·CPU 피크 %·메모리 피크 GiB·IOPS·처리량 MiB/s·네트워크 Gbps·측정 근거를 기록한다. 하드웨어 모델은 설명 정보로 보존한다. 물리 코어 수를 논리 CPU나 AWS vCPU로 임의 환산하지 않는다.

하나의 자산을 하나의 마이그레이션 워크로드로 연결한다. 자동으로 여러 서버를 통합하거나 데이터베이스 부하를 분할하지 않는다. 대상 노드 수·동시 장애 수와 분할 처리 검증 여부는 AWS 계획에서 정한다. 아키텍처 도식은 이 논리 연결을 보여주며 완성된 VPC 설계로 표시하지 않는다.

## 두 산정 경로

| 경로 | 필요한 입력 | 동작 |
| --- | --- | --- |
| 실측 사용량 | 할당 논리 CPU, 피크 CPU %, 피크 메모리와 고정 메모리, 성장률·기간, 목표 활용률, 상대성능 근거 | 워크북 실측 경로로 노드당 요구량 계산 |
| 확정 사양 | 최종 vCPU/노드·GiB/노드 | 성장·HA 여유를 포함해 사용자가 확인한 최종 요구량. 추가 보정 없이 후보 대조 |

사용량이 없으면 실측 결과를 만들지 않는다. 확정 사양 경로로 할당 사양을 검토할 수 있지만 입력 근거를 ‘할당 사양 기준’이라고 보존한다. 상대성능 1은 가정이며 검증된 성능 등가성을 뜻하지 않는다. TTA의 tpmC/max-jOPS만으로 AWS vCPU를 자동 산출하지 않는다.

## 실측 모델과 단위

원문 셀: `AWS EC2!B39:B42`. 수치 입력·결과는 십진 문자열, 중간 연산은 Fraction/Decimal로 보존한다.

```text
growth = (1 + annual_growth_rate) ^ years
survivors = target_nodes - tolerated_failures
divisor = survivors if load_distribution_verified else 1
required_vcpu_per_node = allocated_logical_cpu * peak_cpu_ratio * growth
                         / relative_performance / target_cpu_ratio / divisor
required_memory_gib_per_node = ((peak_memory_gib - fixed_memory_gib) * growth
                               / divisor + fixed_memory_gib) / target_memory_ratio
```

고정 메모리는 피크 메모리에 포함된 값이며 대상 노드마다 필요하다. 음수·0분모·고정분>피크·장애수≥배포수는 오류다. 기간은 초기 버전에서 정수 연도만 받는다. 분할 처리 미검증 시 노드 수로 요구량을 나누지 않는다. 장애 생존 조건은 용량 가정이며 실제 장애전환 검증을 대신하지 않는다.

독립 산술 기준: `16 × 0.35 × 1.2 / 1 / 0.7 = 9.6 vCPU`, `((32−4) × 1.2 + 4) / 0.8 = 47 GiB`. 원본 캐시 PASS를 테스트 근거로 사용하지 않는다.

## 스토리지·후보·비용

gp3는 논리 볼륨 1개/노드의 초안으로 산정한다. 사용 데이터×스토리지 성장÷(1−여유비율)을 올림하고, 요구 IOPS·처리량과 공식 gp3 최소·최대·비율 한도를 함께 적용한다. 기본 3,000 IOPS·125 MiB/s를 포함한 설정값과 업무 실부하 요구량을 구분한다. EC2의 지속 EBS IOPS·처리량과 네트워크 기준 성능으로 후보를 거른다. 순간 최대 대역폭만으로 지속 요구량 충족을 판정하지 않는다.

카탈로그는 공식 사양의 한정된 C/M/R 일반 인스턴스 집합을 버전·URL·확인일과 함께 보존한다. x86_64와 arm64를 구분하고,ARM은 Linux·호환성 확인이 있어야 후보를 제공한다. 리전 가격표에 존재함을 지역 카탈로그 근거로 삼고 실제 AZ 수용량·quota는 별도 확인 사항으로 남긴다. 후보 정렬은 여유 자원과 가격의 기준을 명시한다. 소프트웨어 호환성과 실제 처리 성능의 검증을 사양 충족과 구분한다.

가격은 AWS 공개 가격표의 리전·OS·shared tenancy·On-Demand·통화·유효일·SKU 조건과 함께 보존한다. 누락된 단가는 미산정으로 남긴다. 초기 버전은 수동 가격 입력을 제공하지 않는다. 월 가동 시간은 사용자 입력이다. EC2와 EBS(용량·추가 IOPS·추가 처리량)를 항목별 계산하고 제외 비용을 함께 출력한다. 전체 TCO나 실제 청구액으로 표현하지 않는다. On-Prem 비교 비용도 동일 범위의 사용자가 제공한 비용이 없으면 절감률을 제시하지 않는다.

## 화면 설계

상위 탭은 On-Prem / AWS다. On-Prem에서는 대시보드·서버 자산·TTA/네트워크 계산·근거를 제공한다. ‘AWS 이전 설계’가 선택 자산을 유지한 채 AWS 마법사로 이동한다.

AWS 마법사는 ① 원본 확인 → ② 이전 조건 → ③ EC2·EBS 후보 → ④ 검토·저장 순서다. 후보 표는 vCPU·메모리·지속 네트워크·EBS·월 비용·선정 이유를 비교한다. 우측 패널에는 선택 후보의 병목 조건·출처·검증 필요 사항을 표시한다. 원본·필수 입력 변경 시 과거 추천을 최신 결과처럼 사용하지 않는다.

AWS 대시보드는 저장한 이전안, 자산별 매핑, 전체 예상 비용의 산정/누락 범위, 사양과 가정 변경을 보여준다. 비용이 일부 누락되면 알려진 금액의 소계로 표시한다. 시나리오 비교는 같은 자산과 같은 비용 범위만 변화율을 계산한다.

## 검증 목표

- 독립 산술 9.6/47/450, 분산 여부·장애·고정 메모리·0/누락·범위·잘못된 JSON 검증.
- ARM 미확인, OS 충돌, 리전 미지원, 지속 대역폭·EBS 부족, gp3 한도, 후보 없음, 가격 누락 검증.
- 원문 MB를 GiB로 자동 이전하지 않고, 기존 엔진 21식의 결과·단위·trace 불변 확인.
- 실제 브라우저에서 자산 입력·CSV 가져오기→AWS 이동→조건 수정→후보 선택→저장→비교→인쇄/JSON 재현.
- Cloudscape 실제 컴포넌트·키보드/오류 상태·좁은 화면·인쇄 화면 검토. 구현되지 않은 동작을 완료된 버튼처럼 배치하지 않음.
