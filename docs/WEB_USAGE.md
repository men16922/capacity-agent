# 웹 대시보드 사용 가이드

2026-09-28 · 기획·설계 문서는 [문서 안내](README.md)에서 찾을 수 있다.

## 실행과 저장

루트 [README](../README.md)의 환경 설치·빌드 후 `make web-start`를 실행한다. API와 production 화면은 `http://127.0.0.1:8765`에서 함께 제공된다. 서버는 loopback에만 바인딩하고 `localhost`/`127.0.0.1` 호스트만 허용한다. 인증 없는 이 로컬 구성을 그대로 외부 호스팅하지 않는다.

개발 시 두 터미널에서 `make web-start`, `npm run --prefix web dev`를 실행하고 `http://127.0.0.1:5173`으로 접속한다. 개발 서버는 `/api`를 8765로 전달한다. 브라우저 저장소는 접속 주소별로 구분되므로 주소를 바꿀 때는 프로젝트 JSON을 사용한다.

## 프로젝트 선택과 화면 이동

첫 화면은 `프로젝트` 목록이다. `프로젝트 생성`에서 이름을 입력하거나 `48개 자산 예제`를 선택한다. 프로젝트 이름을 누르면 통합 대시보드가 열리며 좌측에 On-Prem과 AWS 메뉴가 함께 표시된다. 상단 경로에서 프로젝트·환경·자산 위치를 확인한다. `프로젝트 목록` 또는 상단 `Capacity Agent`로 돌아가 다른 프로젝트를 고른다.

각 프로젝트의 On-Prem/AWS 자산·산정안·초안·산정서는 독립적으로 보관한다. 새 프로젝트와 JSON 가져오기는 기존 프로젝트를 유지하고 새 항목을 추가한다. 같은 이름도 가능하므로 프로젝트와 자산 범위를 확인한다. 현재 브라우저의 IndexedDB에 저장되며 사용자 계정·서버 협업 저장은 아니다.

이전 버전의 단일 프로젝트는 최초 접속 시 보존하여 옮긴다. 구버전 탭도 새로고침한다. 저장 중 표시가 끝난 뒤 창을 닫는다. 다른 탭에서 같은 프로젝트를 변경하면 오래된 편집의 덮어쓰기를 막고 JSON 백업·새로고침을 안내한다. 손상된 이전 저장값은 자동 삭제하지 않는다.

## On-Prem

1. `서버 자산`에서 이름·역할·OS·논리 CPU·GiB·논리 디스크 사용량을 등록한다. CPU 피크·메모리 실사용·I/O·네트워크와 측정 근거도 기록한다.
2. 여러 서버는 `CSV 양식`을 내려받아 작성한다. 숫자에 단위를 넣지 않고 열 이름을 유지한다. 1MB·프로젝트 200개 자산 한도이며 잘못된 행이 있으면 전체 가져오기를 취소한다.
3. 자산 편집의 `견적 검토 정보 (선택)`에서 자산 유형·운영 환경·애플리케이션·OS/제품 버전·라이선스·의존성·복구 요구를 기록한다. 빈 값은 미확인이며 자동 판정하지 않는다. [항목별 공식 근거](ESTIMATION_INPUTS.md)를 참고한다.
4. `용량산정`에서 TTA R3, 강의 네트워크, 2021 가이드 중 기준을 고른다. 초기값은 출처/합성 예제이며 수정한 값의 근거를 입력한다.
5. 값을 바꾸면 같은 Python 엔진으로 재계산한다. 필수 입력·단위·출처 오류가 남으면 저장하지 않는다. 변수·옵션·단위를 고급 영역에서 확인하고 JSON으로 전체 요청을 편집할 수 있다.
6. 완성한 결과를 저장하면 산정서를 볼 수 있다. tpmC/max-jOPS는 시스템 성능 지표로, 임의 코어 수 변환을 하지 않는다.

### 자산 상세와 실사용 최적화

자산 목록은 25개씩 표시한다. 서버 이름을 누르면 상세가 열리며 `자산 수정`으로 편집한다. CPU는 피크 사용률을, 메모리는 실사용 GiB 또는 사용률을 입력한다. 디스크는 논리 할당량과 실사용 GiB 또는 사용률을 입력한다. 사용률 방식은 할당량 × 사용률 / 100으로 환산하며 기존 GiB 방식과 같은 수치를 산출한다. 실제 사용량이 할당량을 넘으면 저장·계산을 거부한다.

상세의 `실사용 최적화` 탭에서 성장률·기간·목표 활용률·고정 메모리·디스크 여유율을 검토한다. `최적화 제안 계산`은 현재와 같은 CPU 성능의 계획 요구량과 정수 올림값을 보여준다. 입력을 바꾸면 재계산해야 저장할 수 있다. 이름과 검토 확인 후 저장하면 산정서로 이동한다.

`산정 시나리오`에서 같은 자산·모델 버전의 최적화안 두 개를 선택해 비교한다. TTA·네트워크 업무 요구량은 아래의 별도 목록에 표시하며 사용률 최적화 수치와 교차 비교하지 않는다. 용량산정의 시나리오 이름은 한글로 입력할 수 있고 계산용 ID와 분리해 저장된다.

## AWS 운영 자산과 최적화

`AWS 자산`에서 현재 운영하는 EC2를 등록하거나 CSV로 가져온다. 유형을 선택하면 서울 카탈로그의 CPU·메모리를 적용한다. 피크 사용률·실사용량·측정일·기간/통계의 근거를 입력한다. 현재 gp3의 할당량·프로비저닝 IOPS·처리량을 넣으면 현재 비용도 비교한다. I/O 지속 요구량과 현재 프로비저닝 사양은 다른 항목이다.

`최적화` 목록에서 자산을 선택하고 조건을 검토해 제안을 계산한다. 결과는 필요량, 조건을 충족하는 EC2·gp3, 현재/제안 월 비용과 차이를 제공한다. 차이는 현재 − 제안이므로 양수는 감소, 음수는 증가다. 현재 gp3 사양이 없으면 비용 차이는 계산 불가로 남는다. 확인한 결과는 `최적화 시나리오`에 저장·비교하고 산정서로 출력한다.

이는 사용자 측정값 기반의 결정론적 계획이다. AWS Compute Optimizer 연결·시계열 분석·EC2 변경을 실행하지 않는다. EBS 축소는 새 볼륨으로 데이터 이동·검증이 필요하다. 후보·가격 범위와 공식 출처는 각 결과에서 확인한다.

## AWS 마이그레이션

1. 프로젝트의 좌측 `AWS → AWS 마이그레이션`을 연다. 등록한 서버 전체가 목록에 표시된다. 한 행은 한 서버/VM이며 역할이 같다고 합산하지 않는다.
2. 서버 이름·ID·장비를 검색하거나 역할·산정 상태를 필터링한다. 이름/상태/비용 정렬, 25/50/100개 페이지를 지원한다. 표가 넓으면 표 내부를 가로로 스크롤한다.
3. 행 체크박스로 선택한다. 표 머리글 체크박스는 **현재 페이지**를 선택한다. `검색 결과 N개 전체 선택`은 필터에 맞는 모든 페이지를 선택하며 기존 선택을 대체한다. 페이지/필터를 바꾸어도 선택은 유지되므로 버튼의 선택 건수를 확인한다.
4. `공통 조건 적용`으로 성장률·기간·목표 CPU/메모리 활용률·월 사용시간을 입력한다. 빈 항목은 각 자산의 값을 유지한다. OS·ARM·상대성능·분산 처리 검증은 개별 확인한다. 실측 성장·활용률은 확정 사양의 vCPU/메모리를 바꾸지 않는다.
5. `선택 N개 산정`을 누른다. 완료 건수와 자산별 상태가 표시된다. 입력 오류나 후보 없음이 있어도 나머지는 계속 처리한다. `산정 중지` 또는 화면 이동 시 진행 요청을 취소하고 완료 건은 유지한다.
6. 서버 이름을 누르면 해당 자산의 상세로 이동한다. `이전 요약`, `원본 사양`, `이전 조건`, `EC2 후보`, `계산 근거` 탭에서 비교한다. `이전 대상 목록`으로 돌아오면 필터·페이지·선택을 유지한다. 상세 URL은 같은 프로젝트가 있는 브라우저에서 새로고침할 수 있다. 프로젝트 데이터 자체를 URL로 공유하지는 않는다.
7. `이전 조건 편집`에서 기존 4단계 편집기를 연다. 조건 변경은 초안에 즉시 저장되고 화면 상단에도 안내한다. `상세로 돌아가기`로 이동해도 변경한 초안은 유지된다. 원본이나 조건이 바뀌면 `재산정 필요`로 표시하고 비용 소계에서 제외한다. 저장 이전안의 `복제하여 수정`은 별도 편집이므로 `취소`하면 복제본을 저장하지 않는다.
8. 개별 상세의 `이 자산 재산정`으로 최신 후보를 구한다. 후보 탭에서 다른 EC2를 선택할 수 있다. 현재 선택이 새 조건에도 맞으면 유지한다. 후보 전체를 조회하지 못한 경우 재시도 전까지 저장할 수 없다.
9. 여러 건은 목록에서 선택한 뒤 `선택 N개 검토 후 저장`을 누른다. 각 자산의 최신 후보·월 소계·중복 상태를 확인하고 검토 체크 후 `이전안 N개 저장`을 누르면 이전안 목록에 각각 저장된다. 미산정·재산정 대상·동일 저장안·200개 한도 초과가 있으면 전체 저장을 막는다. 단건은 가정·후보·비용 범위를 검토한 뒤 `검토 후 저장`에서 이름과 확인을 입력한다. 이때만 별도 이전안/산정서가 만들어진다. 일괄 산정만으로 검토 완료 처리하지 않는다.
10. `목록 CSV`는 현재 검색/필터의 모든 페이지를 내보낸다. 최신 결과의 후보·노드·gp3·금액만 포함하며 미산정/오류/재산정 대상은 금액을 비워 둔다. 프로젝트 전체를 보존하려면 `프로젝트 JSON`을 사용한다.

| 표시 상태 | 의미·다음 행동 |
| --- | --- |
| 미산정 | 조건을 확인하고 산정 |
| 후보 검토 | 현재 조건에 맞는 후보 존재. 실제 호환성·부하 검증 후 저장 |
| 입력 확인 | 상세의 오류 항목 보완 |
| 후보 없음 | 요구량·대상 조건과 제한된 카탈로그 범위 검토 |
| 요청 실패 | 서버 연결을 확인하고 다시 산정 |
| 재산정 필요 | 원본·조건·카탈로그 변경. 과거 결과는 소계에서 제외 |

월 소계는 전체 프로젝트 중 **현재 입력과 일치하고 선택 후보 가격이 있는 자산**만 합산한다. 필터를 바꾸어도 상단 지표는 전체 프로젝트 기준이다. 포함 건수 `N/전체`와 EC2+EBS 범위를 확인한다. 세금·전송·백업·추가 라이선스·이관 공수 등 전체 견적 비용은 포함하지 않는다.

## 개별 계산 조건

- **실측 경로**: CPU·메모리 피크, 성장률·기간, 목표 활용률, 상대성능, 노드별 고정 메모리를 사용한다. **확정 사양**: 이미 성장·장애 여유를 반영한 최종 vCPU/GiB를 입력한다.
- 분할 처리를 확인한 경우만 장애 후 생존 노드 수로 부하를 나눈다. 미확인 시 각 노드가 전체 부하를 처리한다. 고정 메모리는 노드마다 복제된다.
- IOPS·MiB/s·Gbps는 성장·장애 상황을 고려한 **노드당 최종 실부하**다. ARM은 Linux와 명시적 호환성 확인이 필요하다.
- 후보는 vCPU→메모리→동일 사양 비용 순으로 정렬한다. 인스턴스명을 누르면 지속 네트워크·EBS 사양과 공식 근거가 우측에 열린다.

예제 WEB/WAS에서 고정 메모리를 `4 GiB`로 입력하면 요구량 `9.6 vCPU / 47 GiB`, gp3 `450 GiB / 6,000 IOPS / 200 MiB/s`를 얻는다. 2026-09-27 카탈로그의 첫 후보는 m8i.4xlarge다. 730시간·1개 노드 기준 소계는 `$821.2856/월`이며 화면에는 `$821.29`로 표시한다. 실제 청구액·전체 TCO가 아니다.

## 비교와 산정서

`이전안·시나리오`에서 한 개를 골라 `복제하여 수정`한다. 원본 자산을 나중에 수정했어도 복제는 저장 당시 사양을 유지한다. 현재 사양으로 시작하려면 마법사에서 서버를 다시 선택한다. 두 개를 선택하면 같은 자산·리전·모델의 결과와 가정 차이를 비교한다.

`산정서`는 당시 입력·가정·식·결과·비용·공식 근거를 제공한다. `인쇄 / PDF 저장`으로 인쇄 창을 열어 PDF로 저장한다. 마이그레이션 예제는 A4 4페이지로 검토했다. 브라우저 인쇄 시 탐색 메뉴가 접히면 좌측의 `탐색 메뉴 열기`로 복구할 수 있다.

`프로젝트 JSON`은 전체 프로젝트를 왕복하는 최대20MB 파일이다. 가져올 때 구조를 검사하고 모든 저장된 산정을 현재 엔진·카탈로그로 다시 실행한다. 구조 오류·통신 실패 또는 저장 이전안을 재현할 수 없는 경우 기존 프로젝트를 보존한다. 검토 전 초안의 입력 오류/후보 없음은 현재 엔진이 재계산한 상태로 가져온다. 변경 전 스냅샷의 초안은 재산정 필요 상태를 유지한다. 개별 `산정서 JSON`은 검토·재현을 위한 보고서이며 프로젝트 가져오기 파일과 형식이 다르다.

## Wiki와 원문

Wiki는 제목·분류·본문 검색, 내부 문서 이동, 공식 외부 링크를 제공한다. TTA는 공식 문서명·표준번호·공식 웹 링크를 우선 표시한다. 단위는 `MB(원문 표기)`, `배율`로 읽기 쉽게 표시하지만 계산 JSON은 기존 단위를 유지한다. 표준 개정일과 입력 기준일은 별개다. 원본은 공개 저장소에 포함되지 않으며 공식 링크를 확인하지 못한 파일은 `원본 별도 (공식 링크 미확인)`로 표시한다. 로컬 원본 PDF 링크는 해당 물리 페이지로 이동한다. 클라우드 보안 가이드는 참고 자료이며 화면이 실제 취약점 점검을 수행하지 않는다.

## 48개 자산 테스트 파일

- 파일 없이 둘러보려면 AWS 목록의 `48개 예제`를 누른다. 추가 안내의 `계속`을 누르면 별도 프로젝트에 미산정 합성 On-Prem48개와 AWS 운영 예제1개가 열린다. 원본 자산·실제 측정값으로 오인하지 않도록 예제 표시를 유지한다.
- [프로젝트 JSON](../examples/migration-portfolio-48.json): `프로젝트 가져오기`로 새 프로젝트에 추가한다. 기존 프로젝트는 유지된다.
- [자산 CSV](../examples/migration-portfolio-48.csv): `서버 자산` → `CSV 가져오기`로 기존 프로젝트에 추가한다. 중복 가져오기는 별도 자산으로 추가되므로 한 번만 가져온다.
- 예제는 WEB·WAS·DB·BATCH·CACHE·API 각 8개, Linux/Windows 혼합이다. 실제 고객 정보나 운영 측정값을 포함하지 않는다.
- AWS 목록에서 전체 48개 선택 → 산정 → 자산별 상세 검토를 시도한다. 새로고침 후 초안/선택 후보는 유지되지만 목록 필터·페이지·체크박스 선택은 초기화한다.

프로젝트 한도는 환경별 자산 200개, 마이그레이션 초안 200개, 저장 이전안·최적화안 각각 200개, TTA/네트워크 계산 묶음 30개, JSON 파일 20MB다. 브라우저별 저장 한도는 다를 수 있으므로 백업을 보관한다.

## AWS 카탈로그 갱신

[빌더](../scripts/build_aws_catalog.py)는 명시적으로 내려받은 공식 자료만 읽는다. AWS 자격증명은 사용하지 않는다. 임시 폴더에 `capacity-aws-gp.md`, `capacity-aws-co.md`, `capacity-aws-mo.md`와 서울 가격 CSV를 준비한다. 문서는 `https://docs.aws.amazon.com/ec2/latest/instancetypes/gp.md` 등에서, 가격은 [공식 서울 Price List](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonEC2/current/ap-northeast-2/index.csv)에서 받는다.

```sh
python -m pip install -r requirements-catalog.txt
python scripts/build_aws_catalog.py --source-dir /path/to/downloads \
  --price-csv /path/to/seoul.csv --verified-on YYYY-MM-DD
```

gp3 한도는 빌더의 명시적 스냅샷이다. 갱신 시 [공식 gp3 사양](https://docs.aws.amazon.com/ebs/latest/userguide/general-purpose.html)과 함께 검토한다. 카탈로그 diff·가격 조건·지속 성능·단위 및 기존 golden fixture의 변경 이유를 검토하고 검증을 다시 실행한다. 카탈로그는 특정 AZ의 수용량이나 계정 quota를 보장하지 않는다.
